# 部署包本机验收记录

日期：2026-10-19。测试为 Windows Docker Desktop 的 Linux 容器，不是真实云服务器。范围是单机部署准备、真实 MySQL 数据兼容和故障边界，不包含公网上线、学校身份/真实数据或付费模型验证。

## 已验证

- 后端完整 `mvn -DskipTests=false test`：校园 84 项、AI 61 项；0 失败、0 错误，3 项可选外部 Redis 测试跳过。额外修改后的管理员初始化专项再次通过。模型并发测试用并行线程和失败操作验证槽位拒绝与 finally 释放，不调用实际模型。
- 两服务打包，三个应用 Docker 镜像构建，Compose 配置检查、Bash 脚本语法检查通过。MySQL 8.4、Redis 7.4、JRE、Nginx 使用已拉取的官方 digest。底层版本的全量安全审计仍未做。
- 独立 `campus-deploy-accept-b` 栈：两个 prod 应用从空 MySQL 库执行 Flyway V1 并通过 Hibernate validate；只有首次平台管理员，没有种入演示账号/社团/资料；两个应用只挂载各自数据库密码，数据库不发布端口。
- 本机 127.0.0.1:8088/8448 的 Nginx HTTP/HTTPS 与 SPA/API 路由通过。测试专用自签名证书通过 `NODE_EXTRA_CA_CERTS` 显式信任，未关闭 TLS 验证，没有在浏览器绕过证书警告；这不是正式公信证书或公网 TLS 验收。
- `scripts/check-deployment.mjs`：实际管理员登录、Secure Session、未登录管理拒绝、超过 255 字节的中文知识正文完整入库、LOCAL 摘录引用、账号日额度与全局日额度拒绝并带 Retry-After、公开校园查询继续可用。LOCAL 不发生真实模型推理。
- 隔离 AI 容器停止后，AI 状态明确 503，而校园查询 200。Redis 容器停止后，新 AI 请求 503，公开校园查询和已授权历史可读；Redis 重新启动后当天已耗尽额度仍返回 429，AOF 没被清空。
- 实际运行 `manage.sh backup`：暂停写入后导出两库；`restore-trial.sh` 在全新无网络容器恢复，全部规范化行数据摘要相同，源库没有被覆盖，测试容器已停止并保留数据卷。
- C→D→C 的同数据库/同部署拓扑应用更新、备份与回滚通过。测试版本是同一阶段代码的独立镜像标签，用于验证部署切换，不代表跨不同业务版本/破坏性数据库升级已经兼容。后来增加拓扑摘要检查、代理配置随镜像打包和基础镜像固定；变化后的旧拓扑不能假定可自动回滚。
- 使用关闭状态的原 H2 备份，在另一个全新 MySQL 8.4 中迁移：校园 10 张表 120 行，AI 6 张表 79 行，保留 ID、BLOB、中文与时间；逐表摘要相同才提交，共 199 行。再次导入非空目标被拒绝。原 H2 备份只读，未修改旧业务数据，也未将包含演示账号的迁移演练库公开。
- 修改 MySQL 映射时显式将 AI 正文/引用/向量等长字符串声明为 longtext，避免默认 tinytext 容量不足。迁移工具处理了 MySQL DATETIME 返回 LocalDateTime 与 H2 带时区时间的类型差异；失败尝试的目标 DML 已回滚。
- 最终 E 镜像（含固定基础 digest、管理员初始化查询改动）再次启动并通过 TLS/restored 与额度持久化检查。原有 Windows 开发后端也已更新重启，旧海报、RAG 历史、账号/社团/活动/经费的 restored 验证通过。

证据位于忽略目录 `.run/deploy-*.log`、`.run/deployment-proof.json`、`deploy/backups/`。密码、证书私钥、数据库和备份没有进入 Git。初期失败的隔离数据库与成功恢复试验卷都保留，不删除其他项目容器或数据库。

验收结束已停止本次部署栈、迁移与恢复试验容器，保留数据卷和备份；原开发服务已恢复。变更拓扑后的 E→旧 C 自动回滚被拒绝，当前版本记录未被更改，避免不兼容配置替换。

`check-deployment.mjs flow` 需要显式设置 `DEPLOY_TEST_FIXTURES=1`，目标仅限本机 HTTPS，且测试栈每日账号/全局额度为 2/3、模型为 LOCAL。不要对正在使用的服务器直接运行这些会保留虚构资料/消耗额度的验收；`restored` 仅读取同一证明数据，故障模式仅配合明确停止的隔离容器使用。

## 已知限制与待验收

- Flyway 10.20.1 对 MySQL 8.4 输出“最新已测试为 8.1”的版本提示，本次 8.4 实际迁移/校验/恢复通过；不据此宣称上游所有兼容性已覆盖，正式维护时需评估整套依赖升级。
- 没有真实 Linux 云主机、域名、公信证书、ICP备案、外网端口扫描、异地灾备或长期证书续期验证。
- 没有迁移后完整校园业务/并发容量、真实学校权限或依赖安全审计；没有新增负责人开户界面。
- 旧 AI 模型配置密文的迁移保留通过，但正式复用仍必须携带旧加密主密钥；不得把新主密钥当成可解密旧数据。
- 不运行真实 Ollama/云模型质量验收，遵守用户“暂不做真实模型验收”的选择。每日额度按业务准入次数而非 Token/金额计费；并发限制仅针对一个 AI 实例。
- 真正上线前必须按 README 的验收清单逐项完成，不能把本次本机演练描述成已经上线或生产安全认证。
