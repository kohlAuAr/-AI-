# 平台模型设置

## 管理员怎么使用

登录平台管理员，在侧栏或“我的”进入 **AI 服务设置**（`/platform/models`）。聊天模型和 Embedding 模型独立配置；学生和社团负责人不能读取或修改配置。

本地方式：管理员先在 AI 服务所在服务器部署 Ollama、安装模型并保持运行 → 填写 Ollama 基础地址 → 检测服务并读取模型 → 选择用途对应模型 → 保存待启用配置 → 测试 → 确认启用。地址 `127.0.0.1` 指 AI 服务进程所在机器；容器或分离的模型服务器需配置可达的内网地址。读取 `/api/tags` 仅证明服务可达并列出已安装模型，不代表已加载或能完成所选用途，须进行推理测试。

云端方式：选择 OpenAI 兼容 API → 选择服务商/填写基础地址、模型 ID 和密钥 → 保存 → 测试 → 确认数据使用授权与费用后启用。千问、GLM、DeepSeek 的名称与地址预设是填写辅助，不保证所有型号、套餐或参数兼容。云端模型 ID 由管理员填写，没有伪造固定模型列表。更换地址会清空页面密钥输入；后端也不会把原地址的已保存密钥带到新地址，云端新地址必须重新填写密钥。

“关闭模型能力”不是 Ollama：关闭聊天后保留本地摘录/固定查询；关闭 Embedding 后语义推荐不可用，基础校园业务不依赖它。不会自动转云端，也不下载、启动或替换用户模型，不替管理员购买模型额度。

## 配置、密钥与权限

- 校园服务 `/api/platform/models/**` 验证 Session 中的 PLATFORM_ADMIN；写入、检测和测试均需 CSRF。校园服务以内部密钥和数据库身份转发至 AI 服务，浏览器不能指定 actor 获权。AI 内部接口再次验证 PLATFORM_ADMIN。
- 每个用途保留一份待启用和一份生效配置。保存只递增版本并清除旧测试标记；旧页面不能覆盖新版本。启用前再次实际测试，失败保留旧生效配置。网络中断时先“重新读取”核对结果，不把未收到响应当成确定没生效。
- AI 数据库 `platform_model_profile` 保存配置、测试版本、最后启用时间及管理员 ID。API Key 经 AES-256-GCM 随机 nonce 加密；管理 API 仅返回是否配置，不返回原文或密文。页面不写 localStorage/sessionStorage，退出和身份切换立即清空，迟到响应不会恢复旧管理信息。
- `AI_CONFIG_MASTER_KEY` 是独立的 Base64 编码 32 字节密钥，`scripts/init-local.ps1` 生成并保留已有值。不能使用前端变量或提交 Git。数据库和主密钥应分开安全备份；丢失主密钥不能通过重新生成恢复原凭证。
- 服务器的 `AI_MODEL_ALLOWED_URLS` 限制精确基础地址。默认开发初始化包含本机 Ollama 及三家官方兼容地址；学校内网、专属业务空间地址须由部署人员加入并重启 AI 服务。网页不能扩大此列表。云端必须 HTTPS；HTTP 不跟随跳转，不接受 URL 内嵌账号、查询参数或片段。部署仍需内网隔离/出站规则，不是任意 URL 调用器。
- 新密钥需要加密主密钥；只打开页面不会把环境变量凭证导入数据库，管理员明确保存同地址配置时才可能加密保留其凭证。

## 热切换及向量边界

没有管理配置时，继续使用 `.env.local` / 环境变量。已经启用的数据库配置在 AI 重启时恢复，优先于启动环境变量；改环境变量不会覆盖它。AI 启动仅恢复配置，不调用云端做测试或重新索引；密钥无法解密时启动失败，不能静默丢弃配置或换供应商。

每个同步请求开始时固定一份完整配置，贯穿 RAG、Embedding 与多轮只读 Agent；切换后只有新请求采用新配置。聊天和 Embedding 独立选择，修改聊天不会通过旧 AUTO 设置隐式改变 Embedding。当前仅支持一个 AI 实例，不包含多实例同步或集群配置中心。

更换 Embedding 协议/地址/模型需要确认旧向量处理：推荐缓存以文本和模型版本区分，资料向量只在版本匹配时参加语义检索，旧资料保留关键词检索能力。不会自动重建或删除旧文档；需要新模型向量时重新上传原文。若同一模型 ID 背后的权重被替换，应使用新的版本化模型 ID，当前不根据模型文件摘要自动识别权重变化。

## 本轮验证（2026-10-18）

- 全量 `mvn -DskipTests=false test`：校园 63、AI 50，共 113 项测试通过。新增覆盖角色/CSRF、受信地址/HTTPS、密钥加密脱敏、版本冲突、先测后启用、失败保留、Embedding 确认、同请求快照及持久配置恢复。兼容协议使用可控 HTTP/模拟 HTTPS 传输测试真实 Spring AI 适配器；云端管理测试检查独立凭证、确认与恢复，不连接真实厂商，不是三家付费账号验收。
- `npm run test:model-settings` 通过：管理员调用、CSRF、忙碌防重、身份清空、迟到读写隔离及真实 Vue/Naive UI SSR。原型增加新路由后为 228 项断言、29 个路由，业务/AI/经费/签到/社团设置回归通过。
- 实际本机 HTTP：`node scripts/check-model-settings.mjs flow` 检测 3 个已安装 Ollama 模型，保存、测试、启用相同的原聊天 `qwen2.5:3b` 与原 Embedding `qwen3-embedding:0.6b`，学生真实资料问答返回。保留新模型配置/启用审计及虚构测试会话，没有改旧社团、兴趣、活动或经费记录，没有下载模型或调用收费云端。
- 实际浏览器检查：管理员从导航进入、检测模型、保存后禁用启用按钮、测试通过、弹窗确认启用与成功状态；云端切换/GLM 地址预设也已检查，未填写真实密钥。
- 响应式检查：实际浏览器 1280×900 桌面、375×812 竖屏和 812×375 横屏；两种手机模拟视口未发现横向溢出，表单及确认步骤可操作。不等于真实微信/手机设备或无障碍全项验收。前端构建仍提示入口块超过 500 kB（约 559 kB），不是构建失败。
- `restart-ai.ps1 -BackupData` 后 `node scripts/check-model-settings.mjs restored` 通过，读取相同生效配置与启用审计；原有 RAG 文档/历史恢复检查及真实 Ollama 混合兴趣推荐 restored 仍通过。`init-local.ps1` 连续运行文件摘要不变，现有密钥和模型设置不被覆盖。
- 仅停止经核对的项目 AI 进程后，`node scripts/check-model-settings.mjs offline` 通过：模型配置返回不可用，校园社团查询仍正常；随后恢复 AI，再次 restored 通过。没有停止用户 Ollama、前端或校园服务。

## 尚未包含

没有付费账号真实兼容验收、模型效果/高并发保证、费用账单、用户配额、流式输出、自动故障转移、自动重建索引、服务器 SSH 管理、Nginx/HTTPS 上线部署或正式 MySQL 迁移。云端测试与启用复测可能计费；全校启用前须确定校内数据可否发送给供应商。严格本地时，应在 Ollama 服务器关闭云功能并限制可用模型，不能仅凭使用了 Ollama 地址就承诺数据绝不外传。

界面沿用 PaiSmart 白色/紫色管理主题、系统中文字体和左对齐表单；以“当前生效 / 待启用”及明确的保存、测试、确认步骤表达真实状态，不用营销卡片或虚构健康指标。前端设计技能用于这个信息层次、反馈和手机表单检查，未改变既定视觉方向。
