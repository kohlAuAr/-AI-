# 账号安全与修改密码

## 使用方式

登录后进入“我的”，点击“修改密码”，填写当前密码、新密码和确认密码。学生、社团负责人和平台管理员均可修改自己的密码。修改成功后转到登录页，使用新密码重新登录。取消只关闭表单。

新密码至少 8 个字符、最多 72 个字符，UTF-8 编码不能超过 72 字节，不能与当前密码相同。密码不去除首尾空格，不放入浏览器持久化存储。提交失败时显示具体错误；如果网络中断造成结果不确定，应尝试用新密码重新登录确认，不把连接失败直接解释为密码未更新。

## 后端处理

`POST /api/auth/password` 接收 JSON：`currentPassword`、`newPassword`。身份仅取当前 Session，额外的 userId/username 不改变修改对象。请求必须携带有效 CSRF Token。成功仅返回 `{"status":"OK"}`，不会返回密码、哈希或凭证版本。

`PasswordService` 在事务中对当前账号行加写锁，校验旧密码、密码长度和新旧差异，更新 BCrypt 哈希并递增 `credentialVersion`。账号默认版本为 0。事务成功提交后，控制器使当前 Session 失效。

登录时 `AccountPrincipal` 保存当时的凭证版本。每次已登录请求在 CSRF 检查之前比较数据库当前版本；不一致就清除身份并使旧 Session 失效。因此，其他设备的旧会话在下一次请求时被拦截，受保护的请求返回 401；公开查询仍可匿名使用。已经进入业务处理的在途请求不追溯撤销，也不向离线页面推送退出事件。

账号实体使用 Hibernate `DynamicUpdate`，只写实际变化的列，防止并发保存姓名、专业等资料时把旧快照中的密码和版本覆盖回来。修改资料不会递增凭证版本。

当前开发数据库继续采用 `ddl-auto=update`；已在保留的本机 H2 数据上验证新增默认值为 0 的版本列及原记录读取。正式 MySQL 的版本化迁移仍是独立工作，不能以本次 H2 验证代替。

## 请求频率限制

| 对象 | 规则 | 恢复方式 |
|---|---|---|
| 同一账号登录 | 五分钟窗口中最多 5 次尝试，验证密码前原子占位，覆盖并行请求 | 窗口到期；成功登录立即清除此账号计数 |
| 同一来源登录 | 每分钟最多 120 次，跨账号累计 | 窗口到期 |
| 同一来源注册 | 每分钟最多 10 次，格式错误也计数 | 窗口到期 |

登录密码连续错误 5 次后，即使下一次输入正确密码，也需等待窗口到期。账号存在与否的认证失败文案一致。受限时返回 429、`Retry-After` 响应头以及带等待秒数的错误消息，前端显示该消息。无有效 CSRF 的请求仍由现有 CSRF 机制拦截。

计数存在有容量上限和过期清理的进程内 Map，适合当前单个校园服务实例，不写数据库或 Redis，重启会清空。不属于验证码、学校身份验证、全局分布式限流或生产安全审计。来源使用服务器取得的 remoteAddr，不信任客户端自行填写的 X-Forwarded-For。将来接 Nginx 或部署多个实例时，需根据可信代理拓扑处理来源地址，并单独引入共享计数；不能直接把任意转发头当成可信地址。
