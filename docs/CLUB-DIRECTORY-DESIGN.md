# 社团列表页设计说明

> 历史记录：该卡片网格方案已被用户否定，当前 `/clubs` 已改为独立社群列表。现行设计与验证见 [COMMUNITY-DESIGN.md](COMMUNITY-DESIGN.md)，下文仅保留旧方案记录。

2026-10-04。范围仅 `/clubs`，不改变招新列表、活动列表、详情页、公共导航或已接入业务。

## 视觉方向

校园社团目录，以兴趣探索和快速比较社团为主。左对齐标题、紧邻搜索和分类、信息完整的社团卡片；桌面三列/两列，手机一列。右侧的小型伙伴图形仅为装饰，不冒充真实活动图片或用户数据。

```
标题与入社申请入口                  伙伴图形（手机隐藏）
搜索兴趣
全部 / 科技实践 / 文化艺术 / 运动户外 / 公益服务
结果标题                            匹配数量
社团卡片：名称、简介、标签、时间、地点、成员数、招新状态、详情
```

色彩：正文 `#203353`，次要文字 `#5e6b80`，操作强调 `#255edb`，浅色区域 `#f6f8fc`，卡片 `#ffffff`，分隔 `#dce3ef`。沿用公共社遇标识，不把单页变化推广到全站。中文字体优先 PingFang SC / Microsoft YaHei，标题 28–44px，手机正文 16px；不引入外部字体、图片、动画库或新依赖。

frontend-design 用于明确校园内容和视觉层级、减少无意义营销装饰。UI UX Pro Max 的设计系统检索给出活泼色块方向，但营销首页结构、紫色社交主题及运动主题配色不适合当前目录，未照搬或持久化其自动推荐；这里的蓝白配色是按任务作出的设计选择。使用其筛选换行、选中状态、computed 派生数据和可访问性建议。

## 功能边界

- 仍使用 `clubCatalog`，正常模式显示后端社团事实，纯原型模式显示原型数据。
- 沿用关键词和分类筛选，不改接口、申请、登录、审核或成员逻辑。
- 保留收藏切换，明确其仅保存在当前浏览器，不宣称已经接入账号收藏。
- 社团名称和详情链接仍打开原有详情页；招新关闭的社团仍可查看。
- 分类显示 `aria-pressed`；结果数使用 status；按钮点击区至少 44px；分类可换行。
- 后端读取中/失败与零条匹配结果区分显示，不用空结果掩盖接口错误。
- 样式限定在此组件的 `.club-directory` 下，不改全局样式或其他页面。
