# 负责人经费台账

## 当前范围与入口

经费后端原已实现，本次补齐 Vue 操作页面，不修改数据库结构或计算规则。正常开发模式进入 `/manage/finance`，从负责人工作台导航或活动管理页的“经费台账”链接也可进入。

使用本机 demo 负责人 `photo_manager` / `code_manager`，密码 `CampusDemo123!`；这些都是虚构测试账号。学生不能查看负责人经费，轮播平台管理员不继承负责人权限。

只做活动记账，不做付款、报销申请、多级审批、发票上传、收入管理或学校正式财务系统。金额由校园后端计算，不调用 AI。

## 一条完整业务

1. 负责人选择自己管理的社团。社团汇总显示已设置预算合计、有效支出合计、未设预算活动数。
2. 在活动管理中先保存活动草稿。草稿、已发布或已取消的正式记录均可记账；SAMPLE 占位活动不参与台账。
3. 到经费台账设置该活动预算，例如 `500.00` 元；可以为 0，但不能为负。
4. 录入支出，例如材料费 `120.50` 元、发生日期和说明。后端保存后页面重新读取数据库，显示已支出 `120.50` 元、剩余 `379.50` 元。
5. 支出超过预算时显示负余额与“已超预算”。这是提示，不是付款限制或审批结论。
6. 点击“查看支出明细”，可以看到原始记录、记录人编号、时间和状态。误录时点击“作废这笔记录”，填写原因并确认。
7. 作废后记录、金额、原因、操作人和时间仍保留，但不计入有效支出；不能删除，也不能再次作废。

没有预算时，预算与剩余显示“未设置”，不是余额为 0；社团汇总不是现金余额，也不把未设预算的活动误算成预算足够。

## 请求与数据

| 操作 | 现有后端接口 |
|---|---|
| 社团台账与活动明细 | `GET /api/manage/clubs/{clubId}/finance` |
| 设置预算 | `PUT /api/manage/activities/{id}/budget` |
| 录入支出 | `POST /api/manage/activities/{id}/expenses` |
| 作废支出 | `POST /api/manage/expenses/{id}/void` |

社团汇总接口已经返回活动与支出明细，页面不重复逐笔调用详情接口。金额输入作为十进制文本发送，前端校验最多 8 位整数、2 位小数；支出必须大于 0、日期不能在未来。实际规则和金额计算由后端 BigDecimal / 数据库承担，前端仅格式化服务器结果。

写请求使用现有 Session / CSRF 封装。后端根据当前登录用户及 MANAGER 成员关系校验所属社团；不会相信页面角色开关或调用者提交的 userId。

## 失败与防重

- 支出表单首次提交生成 UUID；失败后锁定该笔内容，重试复用 UUID 和原内容。服务端以活动+UUID 防重，同编号不同内容返回冲突。
- 响应丢失不代表未入账。弹窗可“刷新核对本笔支出”，发现同编号记录后关闭表单，避免新建重复支出。返回后重新新建会生成另一编号，因此提示先核对。
- 保存期间禁用重复提交、社团切换和弹窗关闭。保存失败不显示成功提示，保留输入和错误供重试。
- 写入成功但刷新失败时明确显示“已保存，但刷新失败”，不误报整个写入失败；台账暂时隐藏，刷新后再展示。
- 切换账号、角色或管理社团时同步清空财务记录；异步读取/写入返回后再次检查身份与社团，旧响应不覆盖当前页面。
- 未登录、学生、轮播管理员或未分配管理社团时，前端不请求经费数据。前端限制不代替后端权限校验。

## 源码位置

`frontend/src/community/CommunityFinanceView.vue`：汇总、活动列表、支出明细和三类表单；沿用白底绿色设计、原生 dialog、可展开明细，无图表或新增图片。

`frontend/src/community/finance.ts`：请求封装、上下文隔离、晚响应防护、金额输入校验和显示。`frontend/src/router.ts`：正常模式使用新页面，纯原型模式继续使用原 `ManageView.vue`；保存的旧原型归档不改。

后端仍为 `FinanceController → FinanceService → ExpenseRepository / ActivityRepository`。未改变原有记账或作废 API、事务、权限及已有数据。

## 验收与结果（2026-10-09）

在 `frontend` 执行：

```powershell
npm run build
npm run test:finance
npm run test:business
npm run test:prototype
npm run test:finance:live
npm run test:finance:live -- restored
```

`test:finance` 使用 Mock HTTP + SSR 验证 CSRF、角色/社团范围、未设预算、金额显示、超预算、作废审计、丢失响应后的同笔重试、双击防重、写成功但刷新失败，以及晚返回的账号/社团隔离。

`test:finance:live` 加载实际 Vue 财务客户端，通过正在运行的本机后端进行操作，并用实际数据库结果进行 SSR。新建一份明确标注的虚构活动草稿，不发布、不修改此前活动或台账。结果保存在忽略的 `.run/finance-page-fixture.json`；`restored` 只核对同一份记录，不新建活动或支出。

实际活动 ID 161：预算 `500.00`；先录入 `120.50`，同编号重试未重复记账；再录入 `400.25`，合计 `520.75`、剩余 `-20.75` 并标记超预算。作废首笔后，支出 `400.25`、剩余 `99.75`，两条原始记录和作废审计均保留。其他社团负责人、学生访问此活动经费均返回 403。

只重启经过校验的校园服务，备份关闭后的 H2 文件；AI 和前端不重启。重启后同一活动、预算、支出与审计字段逐项比对通过。

本轮前端构建、财务回归、业务回归、纯原型 SSR 通过；后端全量 92 项既有测试通过。小屏使用可换行按钮、单列金额行、系统中文字体与现有颜色；UI 技能用于表单错误、焦点和布局检查，未采用不匹配的营销模板。

**没有完成实际浏览器点击、手机真机或完整可访问性验收。** 本轮 HTTP + Vue 客户端 + SSR 证明数据和请求链，不冒充视觉/交互验收；MySQL、支付和生产财务合规不在此次范围。
